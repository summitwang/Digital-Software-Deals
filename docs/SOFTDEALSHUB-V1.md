# SoftDealsHub 新版 V1 实施基线

## 目标与范围

英文手机优先商城、中文运营后台。自营零售与代理专属价格并行，付款确认与人工审核交付分开。独立链接工具继续独立运行。暂不优化 OCR、不切换 Telegram CID 上游、不接入供应商付费 OCR。

## 架构决定

- 延续 Next.js + Vercel；商务逻辑集中在服务端，不信任浏览器传来的金额、交付类型、订单归属。
- Supabase PostgreSQL 存储商品规格、订单行、付款事件、库存单件、交付记录、售后及审计日志；Auth 管理买家身份。
- 付款截图与售后附件使用私有 Storage，通过鉴权后的短时签名地址访问。
- 邮件与供应商任务采用事务 outbox + 持久化 worker；任务重试必须幂等。执行平台与费用待实际负载和部署权限盘点后确定。
- 测试和生产数据隔离；Preview 不使用生产写入凭据。生产数据库与 Storage 文件分别备份并演练恢复。

## 核心模型

| 实体 | 职责 |
| --- | --- |
| products / variants | 软件、系统、地区、设备数、时长、资格要求、价格和交付规则 |
| orders / order_items | 订单及成交快照；每行独立计价和履约 |
| payments / payment_events | 支付平台事件唯一键、金额币种核对、退款与异常 |
| inventory_units / reservations | 单件密钥或账号、批次、预留期限与分配归属 |
| fulfillments | 密钥、账号、邮箱开通、人工服务；部分交付及补发历史 |
| tickets / audit_events | 售后及敏感操作审计 |
| agent_prices | 代理价格和批量采购；钱包暂不与机器人重复建设 |
| outbox / jobs | 可靠通知、交付、重试与失败队列 |

库存预留、订单写入必须同一数据库事务；支付迟到、缺货、少付等进入异常队列。订单、付款、交付状态独立，禁止回调覆盖已完成交付。

## 页面与操作

买家：首页搜索和分类 → 商品规格与兼容性 → 购物车 → 邮箱/账户结账 → 付款及审核进度 → 私密交付页 → 售后与教程。

后台：待审核、待发货、待补资料、交付失败、低库存、售后；商品规格管理、采购批次、逐件交付、补发、退款记录、代理价格及报表。

订阅期限和售后保障期限分别保存、展示；不展示无依据的评价分数或即时发货承诺。

1. 已实现待验收：两个付款入口按数据库售价计价；校验整数数量、库存与前台金额；交付类型改从数据库读取。旧页面金额与当前价不符时拒绝并提示重新结账。
2. 待实施：统一商品 ID 结账与实时报价；清理 /product 和 /products 重复入口。当前保留标题查找兼容旧页面，重复标题会拒绝查询，不能作为最终模型。
3. 待实施：补齐 SQL 迁移、事务库存、支付幂等、服务端管理员权限、私密查单和附件授权。
4. 待实施：商品规格、购物车、订单中心、中文后台和售后；完成统一视觉及手机端验收。
5. 待实施：代理价、优惠券、真实购买评价、任务队列、监控与恢复演练。
6. 发布前：盘点线上部署版本、数据库结构及机器人共用表；迁移演练、历史订单核对、回滚演练后再切换正式站。

## 验收与限制

本次纯函数测试覆盖正常促销计价、改价、过期报价、非法数量、缺货、无促销价及非法金额。执行 `node --test tests/checkoutPricing.test.mjs`（Node 24）。

必须另做隔离数据库与路由集成测试：确保金额失败不会创建支付单、上传附件或写库存；验证最后一件库存并发、同一付款重复回调、访客/他人越权、部分交付、补发退款及邮件失败重试。

当前未连接生产数据库、未执行迁移、未验证 Vercel Preview、未测试真实支付；现存库存竞争和查单权限问题尚未修复，不能把本次提交视为完整上线验收。构建使用虚拟环境变量只验证编译，不验证后端服务。
